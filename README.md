# LifeOS

### Личное пространство для привычек, целей и заботы о себе

Планируйте день, отмечайте прогресс, ведите дневник питания и получайте подсказки ИИ в одном адаптивном веб-приложении.

## Возможности

- Регистрация и вход с хешированием пароля; данные аккаунтов изолированы друг от друга.
- Обзор дня, задачи, цели с прогрессом и привычки с сериями отметок.
- Таймер фокус-сессий, история активности и ежедневные отметки самочувствия.
- Персональные ориентиры калорий и КБЖУ с учётом параметров профиля.
- Дневник питания, вода, недельная сводка и оценка блюда по фотографии.
- Перетаскиваемый помощник Луми, чат и персональные советы.
- Светлая и тёмная темы, экспорт данных, мобильная навигация.

Чат и анализ фотографий используют Gemini API и становятся доступны после настройки ключа. Оценки питания по фотографии приблизительны и требуют проверки.

## Технологии

`Node.js` · `JavaScript` · `HTML` · `CSS` · `Gemini API` (необязательно)

## Запуск локально

Нужен Node.js 18 или новее. Внешние npm-зависимости не требуются.

```bash
git clone https://github.com/xirsoev/lifeos-public.git
cd lifeos-public
npm start
```

Откройте [http://localhost:3000](http://localhost:3000). Порт можно задать переменной `PORT`.

Чтобы включить функции Gemini, скопируйте `.env.example` в `.env`, добавьте свой ключ и перезапустите сервер:

```env
GEMINI_API_KEY=ваш_ключ
GEMINI_MODEL=gemini-3.5-flash-lite
```

На хостинге задавайте ключ через защищённые переменные окружения. **Не добавляйте `.env` и ключ API в Git.**

## Данные и приватность

Аккаунты и данные приложения хранятся в JSON-файлах внутри `data/`. Эта папка исключена из Git: репозиторий содержит только исходный код и пустой файл-маркер.

При использовании чата Google получает текст запроса и краткий контекст LifeOS. При анализе блюда выбранное фото отправляется Google после подтверждения; само фото не сохраняется в дневнике. Не вводите в ИИ чувствительные сведения. Ознакомьтесь с [условиями Gemini API](https://ai.google.dev/gemini-api/docs/pricing).

Демо размещено на Railway. Для постоянного многопользовательского запуска настройте постоянное хранилище и резервное копирование, HTTPS, ограничение частоты запросов и восстановление пароля. Не используйте демо для хранения критически важных данных.
